Exploratory scheduling correction
---------------------------------
Job 562428 requested one CPU and 1 GiB per CPU, but remained PENDING with
Reason=PartitionConfig and never executed. Inspection showed ReqTRES mem=1G
while every cosc3500 node reported MEMORY=1 MB to Slurm, despite larger actual
FREE_MEM values. The memory directive was removed rather than replacing it with
an invented value. This is a cluster scheduling configuration issue, not a
program result.

Job 562429 removed the explicit memory request but was also initially pending
with Reason=PartitionConfig. `scontrol show job` reported Account=s4828704,
whereas `scontrol show partition cosc3500` reported AllowAccounts=cosc3500 and
`sacctmgr show assoc` confirmed that the user has the cosc3500 association.
The Slurm script was therefore updated to request account cosc3500 explicitly.

Final benchmark matrix decision
-------------------------------
Use square sizes 512, 1024, and 2048; 1000 generations; density 35%; seed
12345; and 5 repetitions per size. Expected runtimes from the exploratory run
are approximately 7.5, 30, and 120 seconds per repetition. This gives stable
measurements with identical generation counts while fitting the full matrix in
roughly 13 minutes. Sizes 101 and 256 were excluded because 100-generation
runs were too short; 4096 was excluded because five 1000-generation runs would
take roughly 40 minutes before overhead.
